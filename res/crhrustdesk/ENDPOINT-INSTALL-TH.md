# ติดตั้งคอมพิวเตอร์ให้ IT รีโมตเข้า

คู่มือนี้สำหรับชุด Ubuntu ที่ build แล้วใน `target/CrhRustDesk-Ubuntu-Setup` ตัวติดตั้งมีตัวเลือกบทบาทเครื่อง และใช้ server `172.16.1.83` อย่าใช้ Setup dev เดิมที่ชี้ `172.29.0.96`

## เตรียมก่อนติดตั้ง

ใช้ Windows 10/11 x64 และบัญชี Administrator สำหรับติดตั้ง ให้คอมพิวเตอร์เข้าถึง Ubuntu `172.16.1.83` และ API `https://172.16.1.83:8443` ได้ ชุดนี้แนบ CA ภายในของ Ubuntu ดูค่า SHA-256 ใน `INSTALL-UBUNTU-TH.md`

## เครื่องของผู้ใช้งานที่ให้ IT รีโมตเข้า

1. คัดลอก `CrhRustDesk-Setup.exe` รุ่นใหม่ไปที่เครื่องปลายทาง เช่น `172.29.0.52` ปิด CrhRustDesk ตัว portable เก่า รวมถึงไอคอนข้างนาฬิกา
2. ดับเบิลคลิก Setup แล้วให้สิทธิ์ Administrator เมื่อ Windows ขอ
3. เลือก **เครื่องปลายทาง — รับการรีโมตเข้าเท่านั้น**
4. ตรวจ IP/API ของ server และ SHA-256 ของ CA ในหน้าติดตั้ง ยอมรับเมื่อผู้ดูแลอนุมัติให้เชื่อถือ CA นี้ทั้งเครื่อง ห้ามนำ private key ของ server หรือรหัส AD bind ไปใส่ในชุด client
5. กด **Install → Finish** แล้วเปิด CrhRustDesk จาก Desktop หรือ Start Menu ไม่เปิด executable จากโฟลเดอร์ ZIP เก่า
6. รอให้สถานะเป็น **Ready** จด ID และ IP ที่แสดงในแอปหรือเมนู tray แล้วแจ้ง IT เครื่องปลายทางไม่ต้อง Login บัญชี IT ในแอป
7. ให้ IT ทดสอบเชื่อมต่อ แล้วตรวจว่าปลายทางแสดง connection manager พร้อมชื่อบัญชีที่เชื่อมต่อ และสามารถหยุด session ได้ ทดสอบ reboot และการเริ่ม service อัตโนมัติบนเครื่องจริงด้วย

โหมดนี้ไม่แสดงส่วนรีโมตออก และปฏิเสธการเริ่มรีโมตออกจาก client รวมถึงการสลับด้าน ผู้เชื่อมต่อต้องมี permit จากบัญชีที่อนุญาตใน Management ไม่มีการกดยอมรับเพื่อข้ามสิทธิ์สำหรับผู้ที่ยังไม่ได้รับอนุญาต โหมดนี้ใช้กับ desktop session ส่วน terminal, tunnel, camera และหน้าต่าง file-transfer แยกยังไม่รองรับ permit

## เครื่องของฝ่าย IT

1. ใช้ Setup รุ่นเดียวกัน แต่เลือก **เครื่อง IT — รีโมตออกไปยังเครื่องอื่นเท่านั้น** จะติดตั้งโปรแกรมแยกชื่อ `CrhRustDeskIT` โปรแกรมนี้ไม่รับรีโมตเข้า
2. Login ด้วย username/password AD ของตนเองเมื่อเปิดระบบ AD แล้ว เช่น `somchai` รหัสถูกตรวจที่ AD ไม่ต้องตั้งรหัสแยกบนเครื่องปลายทาง
3. ให้ผู้ดูแลกำหนดสิทธิ์ username นั้นใน Management ว่าเข้าได้ทุกเครื่องหรือเฉพาะ ID ใด ตาม [คู่มือ AD และ Management](AD-SETUP-TH.md)
4. ใส่ ID หรือ IP เช่น `172.29.0.52` แล้ว Connect ผู้ที่ได้รับสิทธิ์เข้า desktop ได้โดยไม่ต้องกดยอมรับ ปลายทางยังแสดงการเชื่อมต่อ หากมี target 2FA ต้องผ่านตามเดิม

## ตรวจเมื่อเชื่อมต่อไม่ได้

* ถ้าปลายทางยังขึ้น Connecting ให้ตรวจ server, public key และการเข้าถึงเครือข่ายก่อน ID ที่แสดงบนเครื่องยังไม่ยืนยันว่า server ลงทะเบียนสำเร็จแล้ว
* ถ้าเรียก IP ไม่ได้ ให้ตรวจ TCP21118 บนเครื่องปลายทางและ Firewall ของเครื่องนั้น ตัวติดตั้งตั้ง rule สำหรับ Domain/Private profile จากเครื่องควบคุม `172.29.0.96` เมื่อเพิ่มเครื่อง IT อื่น ผู้ดูแลต้องปรับ IP หรือ subnet ที่อนุญาตด้วย
* ถ้า Login ได้แต่ไม่มีสิทธิ์ ให้ตรวจ username ใน Management ให้ตรงกับชื่อที่ API แสดง เลือกจากรายชื่อหลัง Login ครั้งแรกได้ หรือพิมพ์ชื่อก่อนล่วงหน้าโดยรักษารูปแบบตัวอักษรให้ตรงกัน
* ถ้า AD Login ไม่ผ่าน ให้ผู้ดูแลตรวจ URL LDAP, รหัสบัญชี service และสถานะ AD การตั้งค่าปัจจุบันใช้ LDAP TCP389 ตามที่ผู้ใช้เลือก ไม่เปลี่ยนไปใช้รหัส local ของชื่อเดียวกันเพื่อข้าม AD

## ติดตั้งทั้งตัว IT และตัวรับรีโมตในเครื่องเดียว

ต้องใช้ client และ Setup ที่ build จาก source รุ่นแยกติดตั้งนี้ ตัวติดตั้งรุ่นเก่ายังใช้โฟลเดอร์เดียวกัน

1. รัน Setup แล้วเลือก **เครื่อง IT** จะได้ `C:\Program Files\CrhRustDeskIT\CrhRustDeskIT.exe` เปิดโปรแกรมนี้เพื่อ Login และรีโมตออก
2. รัน Setup อีกครั้ง แล้วเลือก **เครื่องปลายทาง** จะได้ `C:\Program Files\CrhRustDesk\CrhRustDesk.exe` พร้อม service รับรีโมตเข้า
3. แจ้ง ID ของตัวรับรีโมตให้ผู้ดูแลกำหนดสิทธิ์ใน Management ผู้ที่ได้รับสิทธิ์จึงจะรีโมตเข้าเครื่อง IT นี้ได้ ตัวรับรีโมตยังแสดงการเชื่อมต่อและหยุด session ได้ตามเดิม

จะติดตั้งตัวรับรีโมตก่อนก็ได้ ทั้งสองโปรแกรมมี shortcut, ไฟล์ตั้งค่า, กุญแจอุปกรณ์, log และ IPC แยกตามชื่อโปรแกรม ค่า server เก็บใน `connection-profile.json` ของแต่ละโฟลเดอร์ ไม่มี AD password ในไฟล์นี้ บัญชี Windows แต่ละบัญชีต้อง Login ในตัว IT ของตนเอง

การเลือกอีกบทบาทใน Setup จะติดตั้งอีกโปรแกรม ไม่ได้เปลี่ยนบทบาทหรือลบโปรแกรมเดิม เมื่อตรวจอัปเดตจากตัว IT และดาวน์โหลด Setup ให้เลือก **เครื่อง IT** อีกครั้ง ตัวรับรีโมตยังอัปเดตผ่าน Scheduled Task ของตนเอง การถอน `CrhRustDeskIT` ไม่ลบบริการหรือปิดกฎ Firewall ของ `CrhRustDesk`

หากเคยติดตั้ง IT รุ่นเก่าที่โฟลเดอร์ `CrhRustDesk` ให้ติดตั้งตัว IT ใหม่แยกก่อนและ Login ใหม่ การติดตั้งนี้ไม่ย้ายรหัสผ่านหรือกุญแจเดิมอัตโนมัติ เมื่อต้องการใช้โฟลเดอร์เดิมเป็นตัวรับรีโมต ให้ผู้ดูแลเลือก **เครื่องปลายทาง** อย่างชัดเจน และตรวจสิทธิ์ของ ID ที่แสดงหลังติดตั้งอีกครั้ง

ก่อนใช้งานจริงหลัง build ให้ทดสอบเปิดสองโปรแกรมพร้อมกัน, รีโมตจาก IT ออกพร้อมรับรีโมตเข้า, ตรวจบัญชีที่ได้รับ/ไม่ได้รับสิทธิ์, reboot, อัปเดตและถอน IT ขณะตัวรับรีโมตทำงาน รวมถึงตรวจว่า Scheduled Task และ Firewall ของตัวรับรีโมตยังอยู่ การเปลี่ยนนี้ยังไม่ได้ build หรือทดสอบติดตั้งจริง
